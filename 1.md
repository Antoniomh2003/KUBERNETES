# 1. Introducción a Kubernetes (K8s)

## 1. ¿Qué es Kubernetes?

**Kubernetes** (a menudo abreviado como **K8s**, sustituyendo las 8 letras entre la "K" y la "s") es una plataforma de código abierto diseñada para **automatizar el despliegue, escalado, gestión y orquestación de aplicaciones en contenedores**.

Originalmente desarrollado por **Google** basándose en su sistema interno *Borg*, fue liberado como proyecto open source en 2014 y actualmente es mantenido por la **Cloud Native Computing Foundation (CNCF)**, parte de la *Linux Foundation*.

---

## 2. Evolución del despliegue: ¿Por qué necesitamos Kubernetes?

Para entender Kubernetes, conviene revisar la evolución de los entornos de despliegue:

1. **Era del Despliegue Tradicional (Bare Metal):**
   - Las aplicaciones se ejecutaban directamente sobre servidores físicos.
   - Si una app consumía todos los recursos, ralentizaba a las demás.
   - Costes elevados y escalabilidad muy lenta.

2. **Era de la Virtualización:**
   - Permitió ejecutar varias Máquinas Virtuales (VM) con sus propios sistemas operativos sobre un único hardware mediante un hipervisor.
   - Mayor aislamiento y mejor uso de los recursos físicos, pero con el coste del consumo de RAM, CPU y disco de cada SO invitado.

3. **Era de los Contenedores:**
   - Los contenedores (como Docker) comparten el kernel del sistema operativo anfitrión.
   - Son ligeros, arrancan en segundos y garantizan portabilidad ("funciona en mi máquina y en producción").

4. **El problema de la escala y la necesidad de Orquestación:**
   - En entornos reales de microservicios no se tienen 2 o 3 contenedores, sino cientos o miles.
   - ¿Qué pasa si un contenedor se cae? ¿Cómo se balancea la carga entre réplicas? ¿Cómo se actualiza sin interrumpir el servicio?
   - **Aquí entra Kubernetes**, que actúa como el "director de orquesta" de toda esa infraestructura.

---

## 3. ¿Qué problemas resuelve Kubernetes?

Kubernetes ofrece de forma nativa las siguientes capacidades:

* **Descubrimiento de servicios y balanceo de carga:** Expone contenedores con nombres DNS y direcciones IP únicas, distribuyendo el tráfico de red de forma equilibrada.
* **Orquestación de almacenamiento:** Permite montar automáticamente sistemas de almacenamiento (local, en la nube como AWS EBS / GCP PD, NFS, etc.).
* **Despliegues y retrocesos automatizados (Rollouts & Rollbacks):** Puedes describir el estado deseado de tus despliegues y K8s actualiza gradualmente las versiones o revierte cambios si algo falla.
* **Auto-reparación (Self-healing):** Reinicia los contenedores que fallan, reemplaza y reprograma contenedores cuando los nodos mueren, y no sirve tráfico a instancias no saludables.
* **Empaquetamiento automático (Bin packing):** Asigna recursos (CPU/RAM) a cada contenedor y los ubica en los nodos más eficientes según la capacidad disponible.
* **Gestión de secretos y configuración:** Almacena contraseñas, tokens y claves SSH sin necesidad de reconstruir imágenes de contenedores ni exponer datos sensibles en el código.

## 4. Arquitectura de Kubernetes

Un clúster de Kubernetes se compone de dos partes principales: el **Plano de Control (Control Plane)** y los **Nodos de Trabajo (Worker Nodes)**.

```
+--------------------------------------------------------------+
|                        CONTROL PLANE                         |
|  +-----------------+  +-----------------+  +--------------+  |
|  | kube-apiserver  |  | kube-scheduler  |  |  controller- |  |
|  +-----------------+  +-----------------+  |   manager    |  |
|          |                                 +--------------+  |
|          v                                                   |
|      [ etcd ]                                                |
+--------------------------------------------------------------+
                               |
               +---------------+---------------+
               |                               |
               v                               v
+-----------------------------+ +-----------------------------+
|         WORKER NODE 1       | |         WORKER NODE 2       |
|  +-----------------------+  | |  +-----------------------+  |
|  |        kubelet        |  | |  |        kubelet        |  |
|  +-----------------------+  | |  +-----------------------+  |
|  |      kube-proxy       |  | |  |      kube-proxy       |  |
|  +-----------------------+  | |  +-----------------------+  |
|  | Container Runtime     |  | |  | Container Runtime     |  |
|  | (containerd, CRI-O)   |  | |  | (containerd, CRI-O)   |  |
|  +-----------------------+  | |  +-----------------------+  |
|  | [Pod] [Pod] [Pod]     |  | |  | [Pod] [Pod]           |  |
|  +-----------------------+  | |  +-----------------------+  |
+-----------------------------+ +-----------------------------+
```

### 4.1. Plano de Control (Master / Control Plane)
Toma las decisiones globales del clúster (planificación, respuesta a eventos, etc.):

- **kube-apiserver:** Es la puerta de entrada al clúster. Expone la API REST de Kubernetes y recibe todas las órdenes (`kubectl`, dashboards, etc.).
- **etcd:** Base de datos clave-valor distribuida, consistente y de alta disponibilidad que almacena el estado completo del clúster.
- **kube-scheduler:** Supervisa los Pods recién creados sin nodo asignado y selecciona el nodo idóneo para ejecutarlos según recursos, restricciones y afinidad.
- **kube-controller-manager:** Ejecuta procesos controladores en segundo plano (controlador de nodos, de replicación, de endpoints, etc.) para asegurar que el estado real coincida con el estado deseado.

### 4.2. Nodos de Trabajo (Worker Nodes)
Son las máquinas (físicas o virtuales) donde realmente se ejecutan las cargas de trabajo:

- **kubelet:** Agente que corre en cada nodo y se comunica con el API Server. Asegura que los contenedores descritos en los PodSpecs estén corriendo y sanos.
- **kube-proxy:** Mantiene las reglas de red en los nodos, gestionando el enrutamiento de tráfico y el balanceo hacia los Pods.
- **Container Runtime:** El motor que descarga y ejecuta los contenedores (p. ej. *containerd*, *CRI-O*).

## 5. Conceptos y Objetos Fundamentales

Kubernetes gestiona los recursos a través de **objetos** declarados habitualmente en ficheros **YAML**:

1. **Pod:** La unidad mínima de ejecución en Kubernetes. Agrupa uno o más contenedores que comparten almacenamiento, red (misma IP) y especificación de ejecución.
2. **ReplicaSet:** Garantiza que un número específico de réplicas de un Pod se encuentren siempre activas y funcionando.
3. **Deployment:** Abstracción superior sobre los ReplicaSets que gestiona despliegues declarativos, actualizaciones graduales (*rolling updates*) y reversión de versiones.
4. **Service (Servicio):** Proporciona una IP estática y un nombre DNS estable para acceder a un conjunto de Pods, balanceando la carga entre ellos.
5. **ConfigMap y Secret:** Separan la configuración y las credenciales del código y las imágenes del contenedor.

---

## 6. Filosofía declarativa y la herramienta `kubectl`

A diferencia de los comandos imperativos tradicionales (*"crea un contenedor, luego exponlo, luego reinícialo"*), Kubernetes funciona mediante un modelo **declarativo**:

1. Defines el **estado deseado** en un archivo YAML (por ejemplo: *"quiero 3 réplicas de mi servidor web nginx"*).
2. Se lo envías al clúster mediante la herramienta de línea de comandos `kubectl`:
   ```bash
   kubectl apply -f manifiesto.yaml
   ```
3. El plano de control de Kubernetes se encarga de monitorizar continuamente el sistema para que el **estado actual** coincida con el **estado deseado**.
